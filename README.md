# Gallery 751

소속 없는 작가의 그림을, 살 수 있는 자리로 옮기는 마켓.
단일 `index.html` + `api/submit.js`, Vercel 자동 배포.

## 미리보기

- `주소/` — 실제 데이터 (`works.json`, `artists.json`, `founding-artists.json`)
- `주소/?demo=1` — 샘플 데이터로 렌더링 확인.
  샘플 이미지에 `SAMPLE` 이 찍혀 있어 실제 재고와 헷갈리지 않습니다

## 데이터 파일 세 개

### `artists.json` — 작가

```json
[{
  "id": "kim-seoyeon",
  "name": "김서연",
  "tagline": "빛이 방에 들어오는 시간을 그립니다.",
  "activity": "미대 재학",
  "region": "서울",
  "since": 2021,
  "materials": ["유화", "아크릴"],
  "story": "창문으로 들어온 빛이 벽에 만드는 모양을 오래 봤습니다.\n지금은 그 시간대의 색만 모으고 있습니다.",
  "exhibitions": ["2025 교내 단체전 〈사이〉"],
  "portrait": "artists/kim-seoyeon/portrait.png",
  "instagram": "@seoyeon_paints",
  "founding": true
}]
```

- `activity` — `미대 재학` / `졸업 후 활동` / `직장인·취미` / `전업 작가`
- **학교명은 받지도 표시하지도 않습니다.** 학력을 노출하면 취미로 그리는 사람이
  위축되고 미대 중심의 위계가 생깁니다
- `exhibitions` 가 빈 배열이면 **"전시" 제목째 렌더하지 않습니다.**
  비어 있는 게 기본값이고, 부족해 보이게 만들지 않습니다
- `portrait` 는 **얼굴이 아니어도 됩니다.** 작업실·이젤·작업하는 손·팔레트.
  없으면 레이아웃이 텍스트 전폭으로 바뀝니다 (빈 회색 박스 안 생김)
- `since` 없으면 경력 표시 생략

`tagline` / `story` / `activity` 는 등록 폼으로 받지 않습니다.
게시 전에 대화로 물어보고 Gallery 751가 문장으로 다듬어 넣습니다. (아래 부록)

### `works.json` — 작품

```json
[{
  "id": "w-2026-001",
  "artistId": "kim-seoyeon",
  "title": "여름 오후 3시",
  "year": 2026,
  "medium": "캔버스에 유채",
  "size": "45.5 × 53.0 cm",
  "sizeHo": 10,
  "price": 280000,
  "status": "available",
  "framed": false,
  "images": ["works/w-2026-001/main.png", "works/w-2026-001/detail.png"],
  "tags": ["회화", "추상"],
  "custody": "none",
  "provenance": [{ "date": "2026-09-14", "price": 280000, "type": "primary" }]
}]
```

- `status` — `available` / `reserved`(예약중) / `sold`(판매됨 + 채도 down)
- `custody` — `delivered`(수령함) / `stored`(Gallery 751 보관 중) / `none`
- `sizeHo` — 호수. 작품 카드·상세에 **호당 가격**(작품가 ÷ 호수, 100원 단위 반올림)으로 표시됩니다. 없으면 표시 안 함.
  실제 크기(cm)에 가장 가까운 표준 호수(F·P·M)로 넣습니다. 예: 53 × 33.4 cm → 10(M)
- `provenance[].type` — `primary`(작가 판매) / `resale`(재판매)
- **팔린 작품도 내리지 마세요.** 거래가 실제로 일어난다는 증거입니다
- 이미지는 **PNG**, `works/{id}/` 에 커밋, 가로 1600px 기준. 1장만 있어도 됩니다
- **구매자 정보는 저장하지 않습니다.** 날짜·금액·유형만
- 작품 12점 이상일 때만 가격·재료 필터가 나타납니다
- 각 작품은 `주소/#작품ID` 로 바로 열립니다 (인스타 링크에 쓰세요)

### `founding-artists.json` — 초기 입점 10인

```json
{ "capacity": 10, "artists": [{ "artistId": "kim-seoyeon", "joinedAt": "2026-09-01" }] }
```

- **실제 등록한 작가만.** 자리 채우기용 가짜 이름은 절대 넣지 마세요.
  비어 있는 게 정직하고, 정직한 게 이 페이지의 자산입니다
- 10명이 차면 문구가 자동으로 바뀝니다

## 저널 (`#/journal`, `journal.json`)

그림을 처음 사는 분을 위한 안내, 입점 작가 이야기, 갤러리 소식을 싣는 페이지입니다. 글 하나는 `#/journal/글ID` 로 바로 열립니다.
**Gallery 751과 관련된 글만** 올립니다 (일반 미술계 뉴스는 싣지 않음).

```json
{
  "id": "collector-03",
  "date": "2026-09-30T07:30:00+09:00",
  "series": "오늘부터 나도 컬렉터", "no": 3,
  "title": "집에서 그림의 먼지를 관리하는 법",
  "summary": "목록 카드에 두 줄로 나오는 요약",
  "hero": "journal/collector-03/hero.jpg",
  "body": [
    { "lead": "첫 문단 (크게)" },
    { "h": "소제목" },
    { "p": "문단" },
    { "list": [{ "t": "항목", "d": "설명" }] },
    { "img": "journal/collector-03/room.jpg", "cap": "사진 설명", "href": "#w-작품ID" },
    { "note": "작은 주석" }
  ],
  "links":   [{ "t": "판매 기록 보기", "href": "#/records" }],
  "sources": ["출처 한 줄"]
}
```

- **SNS 글을 그대로 옮기지 않습니다.** 같은 사실을 저널 톤(차분한 설명문, 합니다체, 문장을 이어 한 문단 3~4문장)으로 다시 씁니다
- 스레드·인스타그램 언급, "정리해보려고 합니다" 같은 SNS 말투, 댓글·공유 요청, 해시태그는 넣지 않습니다. 수치·사실은 원문과 같게 두고 새 주장은 더하지 않습니다
- `hero` 는 **글자가 없는 사진**을 씁니다 (카드뉴스 이미지 말고 배경 원본). 가로 1024px 안팎 JPG, 아래 빈 공간은 잘라 가로형으로
- 입점 작가 작품이 나오면 `img` 블록으로 작품 이미지를 넣고 `href` 로 작품 페이지를 연결합니다
- **`date` 가 미래면 그 시각까지 안 보입니다.** SNS 예약 시각과 같게 넣으면 같은 시각에 열립니다
- 시리즈 글은 `series` + `no`, 나머지는 `category`(예: `작가 소개`, `소식`). 이전·다음 글은 시리즈 안에서 이어집니다
- 목록은 날짜 최신순. 글 내용은 영어 모드에서도 한국어로 나옵니다

## 거래 기록 — 확인된 거래만

`provenance` 에는 **Gallery 751를 통한 거래만** 들어갑니다. 작가가 신고하는 과거 거래는 받지 않습니다.
자기 신고 판매가는 검증이 안 되고 부풀릴 유인이 있는데, 이 데이터가 Gallery 751의 유일한 자산입니다.

그래서 검증 등급·배지가 필요 없습니다. 화면에 보이는 모든 거래는 확인된 거래입니다.

## 작가 페이지

`주소/#/artist/{작가ID}` — 작가가 자기 링크로 공유하는 자산입니다.

- 호당 가격 = Σ(거래가) ÷ Σ(호수). **거래 2건부터** 표시 (그전엔 "아직 산정 중")
- 가격 추이 차트는 **거래 3건부터.** 점 하나짜리 그래프는 "이 작품은 오르지 않았다"를
  매일 증명하는 UI가 됩니다
- 재판매 로열티는 **지급된 금액을 숫자로** 표시합니다 ("작가 몫 6,800원 지급됨").
  "2% 드립니다"는 약속이지만 금액은 증거입니다

## 판매 기록 (`#/records`)

구매자가 작가별로 **어떤 작품이 언제 얼마에 팔렸는지** 보는 공개 페이지입니다. 메뉴 '판매 기록'.

- 데이터는 따로 없습니다. `works.json` 각 작품의 `provenance` 를 모아서 보여줍니다
- 판매가 생기면 해당 작품에 `status: "sold"` + `provenance` 한 줄 추가 → 커밋하면 끝
  ```json
  "provenance": [{ "date": "2026-10-03", "price": 800000, "type": "primary" }]
  ```
- 구성: 전체 요약(거래 건수·판매된 작품·최근 거래) → 작가별 표(거래·판매/등록 점수·거래 금액 범위·최근 거래) → 전체 거래 목록(최신순, 작가 탭으로 거르기)
- 거래가 없는 작가도 **0건으로 그대로 표시**합니다. 거래가 하나도 없으면 "아직 기록된 판매가 없습니다"
- 작가 페이지에도 같은 표가 '판매 기록'으로 **항상** 보입니다 (없으면 빈 상태 문구)
- `sizeHo` 가 모든 거래 작품에 있으면 '호당 가격 추이', 하나라도 없으면 '거래가 기록' 차트로 그립니다 (거래 3건부터)

## 재판매 2%

**판매자에게 추가로 물리지 않습니다.** Gallery 751가 받는 15%에서 떼어 작가에게 전달합니다.

```
재판매 340,000원
  판매자 부담   15% (= 51,000원)   ← 1차와 동일
  └ 작가에게     2% (=  6,800원)
  └ Gallery 751      13% (= 44,200원)
```

Gallery 751를 통한 재판매에만 적용됩니다. 문구에서 "Gallery 751를 통해"를 빼지 마세요.

## 작가 등록 폼 (`#/sell`, 2026.09.16 간소화)

첫 접수는 가볍게 받고, 자세한 자료는 메일로 따로 받습니다.

| 항목 | 필수 |
|---|---|
| 이름, 이메일, 작품 가격 | ● |
| 프로필 링크, 짧은 소개 | |

- 접수는 시트 「Gallery 751 접수함」 '작가 접수' 탭 맨 위에 쌓입니다.
- '요청 보내기'를 체크하면 submissions@ 에서 자료 요청 메일(사진·작품 정보·설명·이력)이 나가고 상태가 '자료 요청함'으로 바뀝니다.
- 10분마다 메일함을 확인해 '보낸 메일'·'답장' 날짜를 채우고, 답장이 오면 상태를 '답장 옴'으로 바꿉니다(작가·전시 탭). 시트 메뉴 `Gallery 751 → 메일 상태 지금 확인`으로 바로 돌릴 수도 있습니다.

## api/submit.js

| type | 어디서 | 필수 |
|---|---|---|
| `purchase` | 작품 모달의 구매 신청 | name, contact, region + 동의 2개 |
| `storage_notify` | 수장고 알림 | contact |
| `artist` | 작품 올리기 폼 | name, contact(이메일), price |
| `exhibition` | 전시 참가 의향 | name, contact + agreeTerms |
| `community` | 커뮤니티 참여 | contact, role |

- 청약철회 동의(`agreeWithdraw`)와 재판매 2% 동의(`agreeRoyalty`)는 **반드시 기록됩니다.**
  둘 중 하나라도 없으면 서버가 400으로 거부합니다. 분쟁 시 증거가 됩니다

구글 시트 접수함 (`SHEET_WEBHOOK_URL`)
- 시트는 **dongwon@gallery751.com** 계정의 「Gallery 751 접수함」, 코드는 `apps-script/Code.gs` (시트에 붙은 Apps Script 웹앱). 코드를 고치면 배포 관리 → 수정 → 새 버전으로 올립니다(주소 유지). SECRET 값은 레포에 넣지 않습니다.
- 탭: 작가 접수 / 작품(한 점당 한 줄, 대표 사진이 칸 안에 들어감) / 전시 참가 / 구매 신청 / 기타 신청. 새 접수는 맨 위에 쌓이고 상태 드롭다운이 붙습니다.
- 작가가 올린 사진·이력서는 드라이브 「Gallery 751 작가 접수/날짜 이름 (접수 ID)」 폴더에 저장되고 시트에 링크가 걸립니다.
- 시트 전송은 메일과 동시에 나가며 제한 시간 25초(`vercel.json` 에서 함수 maxDuration 30초).
- `apps-script/` 는 `.vercelignore` 로 배포에서 뺐습니다.

알림 메일 수신처
- `artist` · `exhibition` · `community` → `submissions@gallery751.com`
- `purchase` · `storage_notify` → `inquiries@gallery751.com`
- 보내는 주소 `noreply@gallery751.com` — **Resend 에 gallery751.com 도메인 인증이 되어 있어야 발송됩니다.**
  도메인 발송이 실패하면 `onboarding@resend.dev → NOTIFY_EMAIL` 로 한 번 더 보냅니다(제목 앞 `[임시 수신]`).
- 제출자가 이메일을 적었으면 `reply_to` 로 붙어서, 알림 메일에 바로 답장하면 작가에게 갑니다.

환경변수: `SHEET_WEBHOOK_URL`, `SHEET_SECRET`, `RESEND_API_KEY`, `NOTIFY_EMAIL`(임시 수신용),
선택 `NOTIFY_FROM`, `SUBMISSIONS_EMAIL`, `INQUIRIES_EMAIL`

## 부록. 작가 정보는 대화로 받습니다

등록 폼은 6개 그대로 둡니다. 게시 전에 카톡·DM으로 네 가지만 물어보세요.

```
1. 낮에는 주로 뭐 하세요?              → activity, region
2. 주로 뭘 그리세요? 그게 어디서 시작된 건가요?  → tagline, story  ★ 가장 중요
3. 이번에 보내주신 이 그림은 어떤 상황에서 나온 건가요?
4. 그림 그린 지는 얼마나 되셨어요? 전시하신 적 있으세요?  → since, exhibitions
```

- 작가가 말한 표현을 최대한 살리세요. 매끄럽게 다듬을수록 다 똑같아 보이고,
  그러면 아무도 안 삽니다
- 2번 답이 짧으면 "그 중에 제일 마음에 들었던 순간이 있어요?"로 한 번 더
- **완성된 `story` 를 올리기 전에 작가에게 보여주고 확인받으세요.**
  자기 소개가 자기 말이 아니면 공유하지 않습니다.
  작가가 자기 페이지를 퍼뜨리는 게 이 모델의 유통 구조입니다
- 사진은 "작업실이나 작업하는 손 사진도 괜찮아요"라고 먼저 알려주세요
